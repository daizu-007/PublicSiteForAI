100万トークンを「受け付ける」だけでなく、実際のエンジニアリング圧力下で「信頼できる」コンテキストを維持すること。それがGLM-5.2の核心です。

Solid 1M コンテキスト

100万トークンのコンテキストを宣言するのは簡単ですが、実際のエンジニアリング圧力下で安定して維持するのははるかに困難です。GLM-5.2は大規模なコーディングエージェントシナリオ向けに1Mコンテキスト学習を大幅に拡張し、広範な実装、自動研究、パフォーマンス最適化、複雑なデバッグをカバーします。

大規模実装 自動研究 複雑なデバッグ

柔軟な推論モード (High / Max)

effortレベル制御を導入し、モデル能力とタスク実行速度・計算コストのバランスを明示的に調整できます。Highは日常的なタスクに、Maxは複雑な多段階コーディング作業に推奨されます。同等のトークン消費量において、GLM-5.2はGLM-5.1を大幅に上回るエージェントコーディング性能を発揮します。

IndexShare アーキテクチャ

4つのスパースアテンション層ごとに同じインデクサを共有するIndexShareを提案。1Mコンテキスト長でのper-token FLOPsを2.9倍削減しながら、長文脈ベンチマークでGLM-5.1を上回る性能を達成しました。中間学習段階から128Kシーケンス長で訓練されています。

改良MTPレイヤー (+20%)

投機的デコード用のMTP (Multi-Token Prediction) レイヤーを改良し、IndexShareとKVShareを適用。拒否サンプリングとエンドツーエンドTV損失を導入することで、アクセプト長を最大20%向上させ、推論効率を大幅に引き上げました。

Anti-Hack 対策

コーディングRLにおける報酬ハッキングを防ぐため、ルールベースフィルタとLLM判定による2段階検出を導入。エージェントが評価用ファイルを不正に読み取ったり、GitHubから解答をcurlで取得するなどの行為を在线で監視・ブロックし、ダミー情報を返すことで学習の安定性を保ちます。

Pure Open — MITライセンス

地域制限なし、技術的アクセスの壁なし。GLM-5.2はMITオープンソースライセンスで公開され、HuggingFaceとModelScopeで誰でもダウンロード可能。transformers、vLLM、SGLang、xLLM、ktransformersなど主要な推論フレームワークに対応しています。

アーキテクチャ

1Mコンテキストを支える設計

DSA (DeepSeek Sparse Attention) にIndexShareと改良MTPを組み合わせ、100万トークンを効率的かつ安定的に処理するアーキテクチャ。

IndexShare for DSA

4層ごとに軽量なインデクサを共有し、3/4の層でインデクサの内積とtopk計算を削減。

L1 Indexer インデクサを計算 ─ top-k インデックスを生成
L2 Attend 共有インデックスを使用 ─ インデクサ計算をスキップ
L3 Attend 共有インデックスを使用 ─ インデクサ計算をスキップ
L4 Attend 共有インデックスを使用 ─ インデクサ計算をスキップ
▲ 4層グループ ─ FLOPs を 2.9× 削減
L5 Indexer 次の4層グループのインデクサを計算

使い始める

3つの方法でアクセス

GLM Coding Plan、Z.aiチャット、またはローカルデプロイ。お好みの方法でGLM-5.2を利用できます。

1

GLM Coding Plan

Claude Code、OpenCode、ZCodeでお好みのコーディングエージェントで利用。Lite / Pro / Max / Teamプランの全ユーザーに展開済み。モデル名を GLM-5.2 に変更するだけで有効化。Claude Codeで1Mコンテキストを使うには GLM-5.2[1m] を指定。

# Claude Code で 1M コンテキストを有効化
model: "GLM-5.2[1m]"
# effort レベルの選択
thinking_effort: "max" # または "high"
2

Z.ai チャット

ブラウザから直接GLM-5.2とチャット。chat.z.ai で即座に利用可能。GUIでの利用を好む方向けに、ZCodeデスクトップエージェントも提供（/goalコマンドで長期タスク、SSHリモート開発、モバイル操作に対応）。

3

Effort レベル

タスクに応じて推論の深さを調整。

High

日常的なコーディング

バランスの取れた推論深度。日常的な開発タスク、コードレビュー、リファクタリングに最適。レイテンシと品質のバランスを重視。

Max

複雑な多段階作業

最大推論深度。複雑な多段階コーディング、大規模実装、自動研究に推奨。より多くの計算を割り当て、より高い性能を引き出します。

quota 消費について

GLM-5.2は最も能力の高いモデルとして、ピーク時間帯 (14:00–18:00 UTC+8) は3倍、オフピークは2倍のquotaを消費。2026年9月末までの期間限定でオフピーク利用は1倍請求。ZCode経由の利用で6月30日まで1.5倍の実効quota。
